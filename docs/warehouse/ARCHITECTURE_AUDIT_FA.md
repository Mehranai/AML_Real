# بازبینی معماری و وضعیت بیت‌کوین — ۲۰۲۶-۱۰-۲۲

معماری موردنظر: ساختار جدول‌ها تا حد امکان هماهنگ باشد، اما هر شبکه روی VM
خودش سرویس ClickHouse، database، volume و تنظیمات اتصال مستقل داشته باشد.
VM اصلی فقط API شبکه‌ها، Gateway، Analytical Node و Neo4j مرکزی را مدیریت کند.

## نتیجهٔ بررسی

در تنظیمات و کد بررسی‌شده، ادغام دیتابیس‌ها، اتصال اجباری شبکه‌ها به یک
ClickHouse مرکزی یا اشتراک volume بین VMها پیدا نشد. بستهٔ `shared/warehouse`
تعریف schema را در زمان ساخت داخل برنامه‌ها قرار می‌دهد؛ سرویس یا دیتابیس
مرکزی نیست. نام `clickhouse` در هر Compose داخل همان پروژه و VM resolve می‌شود.

| VM | database | محل داده |
|---|---|---|
| TRON | `tron_db` | ClickHouse و volume محلی VM ترون |
| Ethereum | `ethereum_aml` | ClickHouse و volume محلی VM اتریوم |
| BSC | `bsc_aml` | ClickHouse و volume محلی VM بی‌اس‌سی |
| Bitcoin | `bitcoin_aml` | ClickHouse و volume محلی VM بیت‌کوین |
| Main | Neo4j مرکزی | دادهٔ تحقیق و snapshot؛ بدون ClickHouse شبکه‌ها |

پیکربندی نهایی هر پنج Compose با مقادیر آزمایشی بررسی شد. چهار اتصال محلی،
نام databaseها، volumeهای مستقل با محدودهٔ پروژه، انتشار پورت دیتابیس روی
localhost و استفاده از منبع مشترک schema تأیید شدند. هر دو ابزار
`provision_vms.py` و `provision_vms_real.py` نیز نقش‌های مجزا و مسیریابی VM اصلی
به API هر شبکه را حفظ کرده‌اند.

## بررسی بازگردانی اتریوم

انتقال آزمایشی writer/reader اتریوم به جدول‌های جدید از مسیر فعال خارج شده است.
۱۱ فایل runtime و مستندات اتریوم که در آن آزمایش تغییر کرده بودند، با نسخهٔ
قبل از آزمایش تطبیق بایتی دارند. ماژول، ابزار backfill و تست‌های تازهٔ همان
آزمایش هم در مسیر فعال وجود ندارند؛ وابستگی runtime باقی‌مانده‌ای به آن‌ها
پیدا نشد. یک نسخهٔ غیرفعال صرفاً برای بازیابی در پوشهٔ محلی و ignored `tmp`
حفظ شده است و وارد imageها نمی‌شود.

اتصال قبلی schema مشترک به init/check چهار adapter حفظ شده است. این اتصال
افزایشی است: جدول‌های `aml_*` را کنار ساختار قبلی ایجاد می‌کند؛ writer/reader
قدیمی اتریوم، ترون و BSC را جایگزین نمی‌کند. بازگردانی کلی این بخش لازم نبود.
فایل قرارداد نسخهٔ ۱ تغییر نکرده و checksum migration همچنان
`147ccdadef5b7c195af6dff3cc1d576fbc882a9f6912d99862e3d6919c1f6224` است.

## آزمون‌های مجدد همین بازبینی

- ۱۱ آزمون Rust بیت‌کوین پاس شد: ۷ آزمون واحد، ۲ آزمون نگاشت و ۲ آزمون روی
  ClickHouse واقعی موقت؛ شامل انتقال تاریخچه، restart، prevout، UTXO،
  دادهٔ منتشرنشده و reorg.
- ۷ آزمون بستهٔ مشترک پاس شد: ۵ آزمون واحد و ۲ آزمون روی ClickHouse واقعی
  موقت؛ شامل برابری ساختار چهار database، جداسازی شبکه، drift، نصب نیمه‌تمام
  و مرز انتشار.
- ۴۴ آزمون Python ابزارهای VM، اجرای محلی و ممیزی schema پاس شد.
- پیکربندی پنج Compose و توابع تولید محیط هر دو ابزار VM بررسی شدند.

این آزمون‌ها با داده و رمزهای ساختگی در کانتینرهای موقت اجرا شدند. بررسی
چهار database در یک fixture، آزمون استقرار روی چهار VM واقعی نیست. به هیچ
دیتابیس مستقر متصل نشدیم و migration، حذف جدول یا تغییر volume عملیاتی
انجام نشد. هر سه کانتینر موقت همین بازبینی پس از آزمون متوقف شدند.

## اکنون در چه مرحله‌ای هستیم؟

۱. بیت‌کوین به‌عنوان شبکهٔ چهارم و نقش VM مستقل اضافه شده است؛ API و دریافت
بلاک و تحقیق پایهٔ UTXO وجود دارند.

۲. تعریف مشترک schema و init/check چهار شبکه پیاده شده است. مسیر فعال دادهٔ
پایهٔ بیت‌کوین از آن استفاده می‌کند و ابزار انتقال کنترل‌شدهٔ تاریخچهٔ قبلی
بیت‌کوین وجود دارد. این ابزار روی دیتابیس مستقر اجرا نشده است.

۳. یکسان‌سازی کامل ساختار نهایی چهار شبکه تمام نشده است: جدول‌های قدیمی سه
شبکه و writer/reader آن‌ها هنوز فعال‌اند. امکانات AML بیت‌کوین مانند
intelligence/review، clustering، exposure، ریسک توضیح‌پذیر و workerها نیز باز
هستند؛ زیرساخت فعلی به معنی هم‌سطح‌شدن این قابلیت‌ها نیست.
