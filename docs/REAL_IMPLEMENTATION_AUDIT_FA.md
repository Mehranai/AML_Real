# بررسی پیاده‌سازی واقعی سه شبکه

تاریخ: ۲۰۲۶-۰۹-۱۴

این گزارش تفاوت «کد اجرایی»، «شاهد احتمالی» و «قابلیت هنوز تکمیل‌نشده» را مشخص می‌کند. پاس شدن تست واحد به معنی تأیید کل سامانه برای production یا برابری با Chainalysis نیست.

## دامنه بررسی

مسیرهای ingestion و semantic در TRON، Ethereum و BSC، خروجی investigation، شواهد entity و exposure، موتور ریسک مشترک، موجودی و مصرف خروجی Ethereum و BSC در وب بررسی شدند. جستجوی TODO، unimplemented، demo، fake و mock در کد اجرایی، پاسخ ثابت ساختگی در مسیر اصلی نشان نداد. MockRpcهای موجود متعلق به تست‌ها هستند؛ placeholder فیلد ورودی هم داده جعلی نیست.

مسیرهای اصلی همچنان واقعی‌اند: RPC شبکه، استخراج شواهد، ClickHouse، API تحقیق و snapshot در Neo4j مرکزی. در این تغییر، داده‌ای به‌عنوان تراکنش واقعی تولید نشده و ingest آزمایشی یا حذف دیتابیس انجام نشده است.

## موارد انجام‌شده

- [x] TRON: حذف مبلغ u128 موازی از SimpleTransfer و استفاده از مقدار خام UInt256. جمع خالص با BigInt محاسبه می‌شود؛ تبدیل به i128، اشباع و overflow دیگر جهت جریان را عوض نمی‌کند. فایل‌های `aml/types.rs` و `aml/flow_engine.rs`.
- [x] TRON: افزودن decoder واقعی رویداد Swap سازگار با AMM V2 در `aml/receipt_swap.rs`. آدرس emitter، ساختار topics و چهار کلمه ABI بررسی می‌شوند. مقدار ورودی و خروجی باید دقیقاً با transferهای canonical همان pool برابر باشد. نتیجه همراه log index، مبالغ و relationship ID ذخیره می‌شود. این تطبیق نام تجاری یا مالکیت pool را اثبات نمی‌کند.
- [x] TRON: اتصال decoder به fetcher و transaction features؛ برای swap تأییدشده توسط این decoder، ردیف flow-candidate تکراری تولید نمی‌شود.
- [x] TRON: محدود کردن حدس swap به ورودی و خروجی تک‌دارایی؛ ساختن تمام ترکیب‌های ممکن دارایی‌ها حذف شد. نامزد liquidity به شاهد mint یا burn توکن LP نیاز دارد و فقط در زمینه DEX بررسی می‌شود.
- [x] TRON: رویدادهای استنباطی در `semantic_event_builder.rs` اکنون reference انتقال، مبلغ خام، نوع شاهد و وضعیت محدود شدن شواهد دارند. اطمینان طبقه‌بندی آدرس دیگر مستقیماً به معنی تأیید عملیات swap یا bridge نیست.
- [x] BSC: در `semantic.rs` چند انتقال هم‌دارایی جمع می‌شوند؛ مقدار آخر جای قبلی‌ها را نمی‌گیرد. محاسبه در مرز pool/protocol انجام می‌شود تا عبور از router دوبار شمارش نشود. مجموع با U512 محاسبه می‌شود.
- [x] BSC: انتقال self و مقدار صفر از خلاصه جریان کنار گذاشته شده‌اند. NFT در خلاصه fungible جمع نمی‌شود؛ graph و مسیر canonical آن حذف نشده است. محدودیت تعداد transferها، دارایی‌ها و referenceها در evidence مشخص می‌شود.
- [x] Ethereum: حذف اشباع مجموع مبلغ در semantic decoder و استفاده از U512. در bridge ورودی، دارایی محلی در asset_out قرار می‌گیرد تا با amount_out هماهنگ باشد.
- [x] Ethereum: جریان دارایی با `(asset_id, token_id)` گروه‌بندی می‌شود. شناسه‌های مختلف ERC-721 و ERC-1155 دیگر در یک خروجی ادغام نمی‌شوند؛ Token ID کامل در پنل قابل دیدن است.
- [x] Ethereum: پاسخ investigation شامل منبع، شناسه label، وضعیت تأیید و evidence_refs است. برچسب فعال باید به label تأییدشده متصل باشد.
- [x] Ethereum: remote_asset، correlation_key و detector_version که قبلاً ذخیره می‌شدند به خروجی semantic API متصل شدند. correlation_key در این مرحله اثبات اتصال دو شبکه نیست.
- [x] Ethereum: پوشش تاریخچه شامل اولین و آخرین بلاک ذخیره‌شده، پیوستگی بازه و پوشش از genesis است. ابتدا آخرین وضعیت هر بلاک انتخاب و سپس complete بودن بررسی می‌شود؛ complete قدیمی نباید آخرین وضعیت ناقص را پنهان کند.
- [x] موتور مرکزی: policy با نسخه `aml_evidence_v2_verified_inputs` اجرا می‌شود. label بدون تأیید و منبع و reference امتیاز تولید نمی‌کند. exposure به هویت seed و ارجاع تراکنش نیاز دارد؛ در BSC، seed claim تأییدشده نیز بررسی می‌شود. mixer به شاهد log و منبع registry نیاز دارد.
- [x] موتور مرکزی: مقایسه انتقال سریع برای هر سه شبکه تمام بازه UInt256 را پشتیبانی می‌کند. داده غایب، دارایی خالی و مبلغ نامعتبر به شاهد مثبت تبدیل نمی‌شود. استفاده عادی از exchange یا bridge به‌تنهایی نشانه پول‌شویی نیست.
- [x] وب: نبود exposure به‌صورت «مسیری برنگشت» گزارش می‌شود، نه اثبات نبود هرگونه مسیر. وضعیت ناقص تاریخچه نیز مشخص است.
- [x] Ethereum: ماژول واقعی `src/ethereum/holdings.rs` و مسیر `GET /api/ethereum/wallet/{address}/holdings` اضافه شدند. دارایی‌های شناخته‌شده از transferهای canonical در ClickHouse کشف می‌شوند؛ مانده از RPC با eth_getBalance، balanceOf یا ownerOf خوانده می‌شود، نه از تفاضل تاریخچه ناقص.
- [x] Ethereum و BSC: موجودی native، ERC-20، ERC-721 و ERC-1155 در یک بلاک finalized خوانده می‌شود. chain ID و hash بلاک کنترل می‌شوند؛ تغییر hash باعث رد snapshot می‌شود. حداکثر ۱۰۰ دارایی کشف‌شده به‌علاوه دارایی native، چهار درخواست همزمان در هر خواندن و مهلت محدود اعمال شده‌اند.
- [x] Ethereum و BSC: موجودی به پاسخ investigation متصل شد و در payload همان snapshot در Neo4j مرکزی حفظ می‌شود؛ Export همان مشاهده را دائمی می‌کند. مشاهده جدید موجودی، snapshot قبلی را بی‌صدا بازنویسی نمی‌کند. جدول موجودی تجمیعی جدیدی به ClickHouse اضافه نشده است.
- [x] Ethereum و BSC: پنل Holdings مقدار خام را بدون تبدیل به Number جاوااسکریپت قالب‌بندی می‌کند. decimals نامشخص با واحد خام نمایش داده می‌شود. خطای RPC، revert و timeout معادل صفر نیستند؛ موجودی صفر معتبر جداگانه نمایش داده می‌شود. بلاک، زمان مشاهده و وضعیت partial یا unavailable در خروجی مشخص‌اند.

### محدوده دقیق موجودی

این خروجی، وضعیت فعلی در بلاک نهایی‌شده است، نه مانده در انتهای بازه تاریخی انتخاب‌شده برای graph. قراردادها و Token IDهای قابل بررسی از داده‌های ذخیره‌شده کشف می‌شوند؛ توکنی که هنوز هیچ شاهدی از آن در ClickHouse نداریم لزوماً در فهرست نیست. اگر RPC از finalized یا state موردنیاز پشتیبانی نکند، سرویس نتیجه نامشخص می‌دهد؛ مقدار ساختگی یا صفر جایگزین نمی‌کند. پاسخ standalone با `persisted: false` برمی‌گردد؛ در تحقیق ذخیره‌شده مرکزی، provenance همان مشاهده همراه payload حفظ می‌شود.

## معنای خروجی ریسک

امتیاز صفر تا صد یک سیاست شواهدی نسخه‌دار است؛ ML فعال نشده و احتمال آماری یا نتیجه حقوقی تولید نمی‌شود. `UNKNOWN` یعنی شاهد کافی نداریم؛ `NO_SIGNALS` یعنی در شواهد برگشتی سیگنال امتیازدار دیده نشده، نه اینکه کیف پول قطعاً سالم است. تأیید مرجع، صحت محتوای بیرونی آن را خودکار اثبات نمی‌کند و همچنان به فرآیند بررسی انسانی وابسته است.

## محدودیت‌هایی که نباید «تکمیل‌شده» معرفی شوند

- [ ] اجرای تست end-to-end با ClickHouse، Neo4j و RPC واقعی: Docker Engine در زمان این بررسی در دسترس نبود. queryهای جدید اتریوم هنوز روی دیتابیس زنده تأیید نشده‌اند.
- [ ] ساخت و تست imageهای جدید Docker: image قدیمی خودکار با ویرایش سورس عوض نمی‌شود.
- [ ] پوشش تمام ABIهای TRON: decoder جدید فقط swap ساده V2 با یک رویداد در هر pool در یک تراکنش را تطبیق می‌دهد. چند swap در یک pool، flash swap، V3 و ساختارهای مبهم نیازمند decoder اختصاصی‌اند. این موارد به‌صورت تأییدشده جعل نمی‌شوند.
- [ ] Bridgeهای ترون که فقط از طبقه‌بندی و mint/burn حدس زده می‌شوند هنوز candidate هستند. decoder اختصاصی پیام bridge و تطبیق اثبات‌پذیر آن در شبکه مقصد لازم است.
- [ ] اتصال خودکار مسیرهای cross-chain: وجود remote network، receiver یا correlation key به‌تنهایی کافی نیست. تطبیق پیام، finality هر دو طرف و کنترل collision/replay باید برای هر پروتکل پشتیبانی‌شده پیاده و تست شود.
- [ ] نام صرافی و مالکیت آدرس از داده خالی قابل استخراج قطعی نیست. registry و intelligence به داده واقعی با منبع قابل بررسی نیاز دارند. clustering رفتاری به‌تنهایی اثبات مالکیت مشترک نیست.
- [ ] تأیید زنده موجودی Ethereum و BSC با RPC تنظیم‌شده و query کشف دارایی روی ClickHouse واقعی. قابلیت پیاده شده و تست‌های ABI و RPC محلی پاس شده‌اند؛ پوشش تمام توکن‌های کشف‌نشده ادعا نمی‌شود.
- [ ] بازبینی کارایی، بازیابی backup، reorg و replay روی داده و بار واقعی؛ تست واحد جای این آزمون‌ها را نمی‌گیرد.

## تست‌ها و اجرای تغییرات

تست‌های Rust: TRON تعداد ۷۷، Ethereum تعداد ۳۴، BSC تعداد ۴۴ و Analytical Node تعداد ۱۶ تست، در مجموع ۱۷۱ تست پاس شدند. پنج تست یکپارچه BSC به دیتابیس آزمایشی نیاز دارند و ignored باقی ماندند. کامپایل همه باینری‌های سه شبکه هم بررسی شد. تست RPC محلی اتریوم ثابت بودن شماره بلاک، مبلغ کامل UInt256، رد شبکه اشتباه و تشخیص تغییر hash را بررسی می‌کند؛ این تست جای RPC زنده را نمی‌گیرد.

پنج تست routing در gateway پاس شدند. تست مرورگر برای Ethereum و BSC، شناسه UInt256 کامل NFT، قالب‌بندی موجودی، تفکیک صفر از unavailable و نبود overflow را در عرض ۱۲۸۰ و ۳۹۰ پیکسل بررسی می‌کند. تصویر پنل موجودی موبایل نیز بازبینی شد.

از ریشه پروژه:

```text
cargo test --manifest-path dockerizd_tron/app/Cargo.toml --lib --locked
cargo test --manifest-path dockerizd_ethereum/Cargo.toml --lib --locked
cargo test --manifest-path dockerizd_bsc/Cargo.toml --lib --locked
cargo test --manifest-path analytical_node/Cargo.toml --locked
npm run test:evidence
```

تست وب در Windows از Edge و در Linux از Chromium نصب‌شده Playwright استفاده می‌کند. fixture فقط ورودی تست است و در مسیر اجرایی برنامه وارد نمی‌شود.

هیچ جدول یا migration تاریخی تغییر نکرده است. نسخه detectorها تغییر کرده تا منبع شواهد جدید قابل تشخیص باشد. پس از rebuild و restart سرویس‌ها، ingestion جدید از کد جدید استفاده می‌کند؛ بازنویسی شواهد بلاک‌های قبلی نیازمند replay کنترل‌شده همان بازه است. snapshotهای Exportشده قبلی عمداً تغییر نمی‌کنند؛ برای امتیاز سیاست جدید باید investigation جدید ساخته شود.

تغییرات قبلی کاربر در README و اسکریپت provision و فایل‌های env دست‌نخورده ماندند.
